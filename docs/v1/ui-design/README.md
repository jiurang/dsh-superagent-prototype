# 雄大工作台 UI 重构 · 设计任务书

## 目标

当前雄大工作台页面过于“平”：列表 + 表单从上到下堆叠，信息层级弱，项目/需求/任务的关系没有在界面上体现。重构目标不是只换颜色，而是建立一套**能承载多项目、任务流、智能体状态**的工作台界面。

## 必须体现的层级

```text
系统
└─ 项目（多个）
   └─ 需求
      └─ 任务（类型 / 状态 / 优先级）
         └─ 执行尝试 / 证据 / 评审 / 记忆
```

- 系统设置与项目设置必须在视觉上分开；
- 项目是工作台的第一层上下文，不能让用户在全项目混合列表里猜；
- 需求是任务的容器，任务不是孤立列表；
- 执行尝试（Attempt）只出现在任务详情里，不进入任务列表；
- 重要动作（新建需求、拆任务、派发、验收）要就近出现，不要全部堆在页面底部。

## 页面范围

原型至少覆盖：

1. **工作台概览**：项目卡、待处理任务、阻塞、最近活动；
2. **需求页**（重点，截图所示）：需求列表、项目上下文、新建需求、拆任务；
3. **任务页**：任务列表 + 详情（运行记录、证据、评审）。

可以增加：项目切换器、全局搜索、命令面板、侧边抽屉、看板、时间线、分栏等，但必须能落到 React 实现。

## 设计约束

- 中文界面，术语与 `SUPERAGENT-DESIGN.md` 一致；
- 桌面优先，宽度 1200px 左右可用；
- 不引入第三方 UI 库或外部字体/图片；
- HTML 原型必须自包含、可直接浏览器打开；
- 使用模拟数据：`DEMO`（演示项目 · 账单系统）、`NEW_CENTER_APP`（中心应用）；
- 保留现有功能语义：确认需求、拆任务、派发、删除、验收、评审、记忆确认；
- 不要为了“好看”隐藏状态、优先级、阻塞、失败等关键信息。

## 交付物

每个方案目录：

```text
docs/v1/ui-design/proposals/<slug>/
  index.html      # 自包含原型
  notes.md        # 设计概念、布局、交互、实现映射
```

原型应包含可点击的 tab / 卡片展开 / 抽屉或弹窗，展示关键交互；不要求真实后端。

- 需求页 / 任务页：项目栏 + 母版列表 + 常驻详情 + 列表/看板双视图；
