## 逐项说明

### 01-command-center

- **具体优点**：左侧项目组合常驻、顶部当前项目四指标、388px 需求母版与右侧详情同屏，把「系统 → 项目 → 需求 → 任务 → Attempt」五层直接写进布局；拆任务在需求详情内展开，提交前用 chips 逐条预览将生成的任务，确认、派发、验收、评审都贴着对象出现。
- **具体风险**：可读性押在小字号上——元信息 8–9px、正文 10–11px，248px 左轨加 388px 母版后详情只剩约 560px；1200×830 下拆分 composer 的提交按钮已落到折叠线以下（截图需滚动才见），125% 缩放、长证据或上百条列表时还需重排版与虚拟滚动，原型尚未覆盖。

### 03-linear-split

- **具体优点**：需求表用 40px 行距 + 固定表头 + 状态/优先级/来源三种轻量编码，在 1200×830 一屏可扫完 7 条需求；右侧 400px 详情把所属任务、任务状态与拆分 composer 收在同一列，项目页还用「设置作用域」明确画出「系统设置 · 实例 / 项目设置 · 项目」，是三份中对这条约束表达最清楚的。
- **具体风险**：400px 详情把表格压到约 560px，1200px 下中文需求标题已出现截断（如 #121「对账失败时给出可执行的修复建…」），来源列在 1120px 以下被隐藏，元信息 9–10.5px；长标题、长证据或更高缩放时需要更激进的省略与回退策略。

### 05-timeline-flow

- **具体优点**：右侧「此刻」只收需要人判断的事，按 P0 待确认 → 阻塞 → 评审 → 验收 → 记忆排序，并给出一键确认/评审/验收；sticky 项目上下文条把「我在哪个项目」固定在顶部，时间线事件本身可点回需求或任务，是三者中「发生了什么 / 现在要我做什么」分得最干净的概览。
- **具体风险**：项目页只写了「项目设置与系统设置保持分离」的说明，实际没有任何系统设置区块，达不到任务书要求的视觉分层；同时需求展开体和任务列表只用色点表示任务状态（无状态文字），与「状态不能只靠颜色」以及「不要隐藏状态」相冲突。

## 推荐

**01-command-center**：它的信息层级和就地操作最完整，项目切换、需求分组、任务构成、拆分与详情都在一屏内闭合，且系统/项目设置、暂停项目与空状态都有实际界面支撑；主要代价是小字号和密度，属于可通过 type scale 与断点调整的风险，而 05 需要新增活动读模型、03 在窄表格与 400px 详情之间让渡了标题可读性。
